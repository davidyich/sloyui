# Контент и рабочие экраны 0.3

Компоненты собирают календарь, заметки и канбан из тех же токенов, что кнопки и поля. Импортируйте их из `@personal/capacities-ui`; `styles.css` подключается один раз в приложении. Тема задаётся на `html` через `data-theme="light" | "dark"`, локальный акцент — на контейнере через `data-accent`, например `teal` или `neutral`. `data-borders="off"` — вид по умолчанию, `on` включает декоративные рамки. Контраст задаётся явным контекстом `data-surface="base" | "canvas" | "raised" | "floating"`; собственный контейнер должен иметь соответствующий фон. Каждому каноническому компоненту соответствует страница каталога `#ComponentName`, например `#Calendar` или `#ContentCard`.

| Компонент | Основной контракт |
| --- | --- |
| `Calendar` | `mode="single"` + `value/onValueChange` или `mode="range"` + `range/onRangeChange`; `numberOfMonths`, `highlightedDates`, `events`, `showAgenda` |
| `DatePicker` | Те же свойства календаря; `label` подписывает кнопку. Закрывает `Popover` после одной даты или завершённого периода |
| `MarkdownPreview` | `value`, `headingOffset`; отображает поддержанный Markdown через React |
| `RichTextEditor` | Управляемые JSON-блоки; Markdown-мост и исходные блоки описаны в [editor-revision.md](editor-revision.md). `MarkdownEditor` архивирован |
| `ContentCard` | `title`, слоты `header`, `cover`, `description`, `metadata`, `footer`, `actions`, `children`; независимые `onOpen`, `selectable` и `onSelectedChange` |
| `TaskCard` | Карточка задачи: `title`, `typeLabel`, `color`, `completed`, `onCompletedChange`, `menuItems`; остальные слоты наследует от `ContentCard` |
| `KanbanColumn` | `title`, `count`, `color`, `action`, `emptyState`, `children`; цвет ограничен заголовком, поверхность наследуется |
| `KanbanBoard` | `columns`, `items`, `label`; действия `onMove`, `onCompletedChange`, `onOpen`, `onAdd`; необязательный `renderCard` |
| `DailyHeader` | `date`, `locale`, `showWeek`, `tags`, `actions`, `children`; `headingLevel` выбирает уровень заголовка |

## Состояние и данные

Потребитель хранит выбранные даты, текст, карточки, колонки, выделение и завершённость задач. Компоненты вызывают обработчики и не выполняют сетевые запросы, автосохранение или запись в `localStorage`. `RichTextEditor.onValueChange` сообщает новые блоки; успешное сохранение подтверждает приложение после своей операции.

`KanbanTask.id` и `KanbanLane.id` должны быть уникальными в своей коллекции. `columnId` каждой задачи должен указывать на существующую колонку: задачи с неизвестной колонкой не отображаются. Перемещение выполняется через меню карточки, доступное с клавиатуры. `onMove` сообщает намерение — он сам не меняет `items`. Между колонками drag-and-drop не реализован; для вертикального порядка внутри коллекции используйте ReorderableList. При `renderCard` потребитель сам добавляет действия к своей карточке.

`ContentCard` — контейнер `article`. Выбор включается через `selectable={true}` или `onSelectedChange`, если `selectable` отсутствует; `selectable={false}` скрывает и контроль, и выбранную обводку. При `onOpen` только заголовок становится кнопкой; меню, угловой контроль выбора и кнопки в `footer` остаются отдельными элементами. `selectionPosition="top-start" | "top-end"` задаёт угол; контроль не зависит от `header`, `blockOrder` или `hiddenBlocks` и не меняет выравнивание блоков. Без ведущей обложки он выступает за границу: оставьте 12 px зазора и не обрезайте его внешним overflow. При интерактивном содержимом `title` не передавайте `onOpen`, чтобы не вкладывать кнопки друг в друга. Для нетекстового заголовка передайте понятный `selectionLabel`. `density="compact"` уменьшает отступы; `orientation="horizontal"` размещает обложку сбоку на широком экране.

## Состав и порядок карточки

`blocks?: readonly ContentCardBlock[]` принимает `{id, content, kind?, hidden?}`. `kind="metadata" | "footer"` даёт соответствующую типографику; по умолчанию обычный контент. Встроенные ID: `cover`, `header`, `title`, `description`, `content` (children), `metadata`, `footer`. Пользовательский блок с тем же ID заменяет встроенный. `blockOrder` перечисляет ID в нужном порядке, остальные добавляются в конец; `hiddenBlocks` скрывает их. ID должны быть постоянными, не индексами. При скрытии React-узел размонтируется: значимые данные храните в состоянии приложения.

Теги, превью, тип объекта, коллекции, алиасы, даты, счётчик слов и будущие свойства передаются блоками без изменения компонента. Обложка в начале поддерживает `orientation="horizontal"`; перемещённая внутрь становится обычным блоком. Карточки разной ориентации не растягиваются до высоты соседа. `onOpen` относится к заголовку, выделение и действия независимы.

`ReorderableList<T>` принимает `items` с уникальными `id`, `onOrderChange`, `getItemLabel`, `renderItem`. По умолчанию ручка слева; при `handlePlacement="custom"` вставьте `context.handle` в `ContentCard.dragHandle`. Pointer/touch перемещает только за ручку; порядок меняется при отпускании, Escape/pointercancel отменяет. ArrowUp/Down/Home/End и кнопки по нажатию на ручку дают альтернативу перетаскиванию. Поля внутри строк сохраняют состояние при перестановке. Сохранение и перенос между разными списками принадлежат приложению.

## Даты и клавиатура

Даты передаются строками `YYYY-MM-DD`, без времени и часового пояса. Не преобразовывайте выбор календаря через `toISOString()`: это может сдвинуть день. `defaultMonth` принимает `YYYY-MM` или полную дату и задаёт начальный месяц, когда дата не выбрана. При внешнем изменении выбора календарь показывает выбранную дату; уже видимая дата не сдвигает пару месяцев.

`locale`, по умолчанию `ru-RU`, форматирует названия месяцев, дней и даты. Подписи служебных кнопок остаются русскими. Неделя начинается в понедельник, каждый месяц содержит 42 ячейки; в двухмесячном виде соседние даты скрыты, чтобы у каждой даты была одна кнопка. `DailyHeader` показывает номер ISO-недели. `today` позволяет задать локальную дату «сегодня», например для детерминированных примеров. `yearRange` задаёт диапазон поиска ComboBox годов (по умолчанию ±10 лет от today с включением видимого года); `min` и `max` ограничивают сам выбор даты.

- Стрелки перемещают фокус на день или неделю; недоступные даты пропускаются.
- `Home` / `End` переводят фокус к началу / концу недели.
- `PageUp` / `PageDown` меняют месяц, с `Shift` — год. День месяца ограничивается последним существующим днём, например 31 января → 28 февраля.
- `Enter` / `Space` выбирают сфокусированную дату. Переход стрелками сам по себе не меняет `value`.
- `min`, `max` и `isDateUnavailable(date)` исключают выбор и клавиатурную остановку на дате.

`mode="range"` использует управляемый `range?: CalendarRange` (`{start, end?}`) и обязательный `onRangeChange`. Первый выбор сообщает `{start}`, второй — отсортированные `{start,end}`; следующий начинает новый период. Одинаковые границы означают один день. Если между границами есть недоступная дата, второй выбор начинает новый период и сообщает причину. Наведение/фокус показывает предварительный диапазон без изменения выбора. По умолчанию range показывает два месяца, single — один; `numberOfMonths={1|2}` переопределяет это. На узкой поверхности два месяца располагаются вертикально. DatePicker закрывается только после завершения выбора. Для сброса передайте `range={undefined}`.

`highlightedDates` принимает строки дат или `{date,label?,color?}`. Отметка отличается от today и выбора короткой чертой, а label входит в доступное имя даты. Не используйте дополнительные отметки для хранения выбранного периода. Single сохраняет исходный интерфейс `CalendarProps`, обязательный `onValueChange` и не вызывает его при простой навигации. Для типизации range используйте `CalendarRangeProps`, для обоих режимов — `CalendarSelectionProps`; общие свойства вынесены в `CalendarBaseProps`.

`CalendarEvent` содержит `id`, `date`, `title`, необязательные `time`, `description`, `color` и `emphasis="title"|"time"`. `eventEmphasis` задаёт общую иерархию, отдельное событие может её переопределить. Время — готовая строка, без парсинга или часового пояса; при отсутствии времени основной строкой остаётся название. Список показывает все события дня в порядке массива. `showAgenda` включает список выбранного дня (в range — дня с фокусом), `agendaPosition="bottom"|"side"` размещает его снизу или сбоку; узкая композиция переносит боковой список вниз. `showEventPreview` (по умолчанию true) показывает тот же список по наведению/фокусу даты. Escape закрывает подсказку; она не содержит действий. Планирование и проверка пересечений принадлежат приложению.

Calendar сам не рисует панель и наследует поверхность контейнера. Оберните его в Card для raised или используйте DatePicker/Popover для floating; год и расписание используют стандартные порталы и наследуют theme/accent/borders/radius/shadow. При borders=on группа месяца/года имеет общий контур и разделитель, без изменения геометрии при off. Выбор даты плавно перемещает выделение, смена месяца анимирует opacity/transform; reduced motion отключает движение.

Рабочий пример с Card, боковым расписанием и периодом в popup: [`examples/CalendarSchedule.tsx`](../examples/CalendarSchedule.tsx).

## Markdown и редактор

`MarkdownPreview` безопасно отображает небольшой поднабор: заголовки, абзацы, жирный/курсивный текст, inline и fenced code, плоские списки, задачи, цитаты, разделители и ссылки. Разрешены `http`, `https`, `mailto`, якоря и абсолютные пути внутри сайта. HTML выводится текстом, небезопасный URL не становится ссылкой. `headingOffset` по умолчанию `1`: Markdown `#` становится `h2`. Preview не реализует весь CommonMark; изменения задач вносятся в исходник.

Канонический редактор — `RichTextEditor` с JSON-блоками и marks. Для файлов Markdown используйте `markdownToRichText` и `richTextToMarkdown`: нетронутые блоки возвращают исходные байты, неподдержанные таблицы, ссылки, HTML и сложные конструкции остаются редактируемыми исходными блоками. Не удаляйте `RichTextBlock.markdown` при обновлении блока; это данные для сохранения источника. `preserveMarkdownSourceEdit` сохраняет неизменённые окончания строк при работе с textarea. Точный контракт и ограничения: [editor-revision.md](editor-revision.md).

`MarkdownEditor` остаётся deprecated экспортом для прежних потребителей строкового `value` и `onSave`; его ссылка в каталоге ведёт на `#RichTextEditor`. Не подменяйте прежний формат данных новой JSON-моделью без миграции. В редакторе инструкций Rich edit включён по умолчанию, Markdown-переключатель даёт прямое редактирование той же строки; сохранение пишет реальный файл с проверкой ревизии.

## Композиция с панелями

Используйте `ActionBar` для группы инструментов с навигацией стрелками, `ButtonGroup` для визуального объединения и `SplitButton` для основного действия с дополнительным `Menu`. Они принимают `size="xs" | "sm" | "md" | "lg" | "xl"`; выбранный размер согласует вложенные кнопки, Menu/Popover triggers и поля. Вложенная группа может переопределить size. `Popover.size` влияет на trigger, содержимое popup сохраняет собственную геометрию. Если внутри панели есть поля ввода или сложные управляемые элементы, установите `rovingFocus={false}` и оставьте обычный обход по `Tab`.

`ScrollArea` добавляет краевые маски только со сторон, где остаётся прокручиваемое содержимое: они открывают существующий фон без цветной подложки. `scrollbar="auto" | "hidden"` управляет полосой, сохраняя wheel/touch/keyboard; горизонтальный режим по умолчанию hidden, vertical/both — auto. `shadows={false}` отключает маски. Задайте контейнеру ограниченную высоту; `ref` указывает на внутренний прокручиваемый viewport. Канбан имеет собственную горизонтальную область: не оборачивайте его второй горизонтальной прокруткой без необходимости.

`Dialog` / `Drawer` подходят для создания и редактирования карточек; `Input`, `Select` и `Textarea` размещают подпись внутри через `labelPlacement="inside"`; FloatingField делегирует Input. `StatusBar` показывает результат действия: `variant="plain"` по умолчанию оставляет фон прозрачным, `variant="surface"` добавляет подложку. `Alert` показывает подробное состояние или ошибку. Видимость диалога, результат сохранения и время показа уведомления контролирует приложение. Размеры, плавность, фокус и reduced motion уже заданы общими стилями.

`ContentCard`/`TaskCard` используют raised; `RichTextEditor` и `DataTable` наследуют поверхность, у DataTable её можно задать prop. `SidebarPanel.surface` по умолчанию canvas, плавающие панели и popup используют floating. Popup сохраняет локальные тему, акцент и borders, но устанавливает собственный floating-контекст. В собственных слотах не подменяйте фон без соответствующего data-surface: второстепенный текст и нейтральные/акцентные заливки вычисляются относительно этого контекста.

Контракт панелей и карточек: [content-revision.md](content-revision.md); нейтральных статусов, контраста и inline/floating-композиции: [feedback-revision.md](feedback-revision.md).

Рабочий пример с совместимым строковым редактором: [`examples/WorkspaceV2.tsx`](../examples/WorkspaceV2.tsx). Он создаёт задачи, перемещает их между колонками, выбирает дату и редактирует заметку в локальном состоянии.
