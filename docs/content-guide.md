# Контент и рабочие экраны 0.3

Девять компонентов собирают календарь, заметки и канбан из тех же токенов, что кнопки и поля. Импортируйте их из `@personal/capacities-ui`; `styles.css` подключается один раз в приложении. Тема задаётся на `html` через `data-theme="light" | "dark"`, локальный акцент — на контейнере через `data-accent`, например `teal` или `neutral`. `data-borders="off"` — вид по умолчанию, `on` включает декоративные рамки и меняет плотность нейтральных заливок. Контраст задаётся явным контекстом `data-surface="base" | "canvas" | "raised"`; собственный контейнер должен иметь соответствующий фон. Каждому компоненту соответствует страница каталога `#ComponentName`, например `#Calendar` или `#ContentCard`.

| Компонент | Основной контракт |
| --- | --- |
| `Calendar` | `value?: string`, `onValueChange(date)`, `locale`, `min`, `max`, `isDateUnavailable`, `events`, `showAgenda` |
| `DatePicker` | Те же свойства даты; `label` подписывает кнопку. Открывает `Calendar` внутри `Popover`, закрывается после выбора |
| `MarkdownPreview` | `value`, `headingOffset`; отображает поддержанный Markdown через React |
| `MarkdownEditor` | `value`, `onValueChange`, `label`; режимы `edit`, `preview`, `split`, необязательный `onSave` |
| `ContentCard` | `title`, слоты `header`, `cover`, `description`, `metadata`, `footer`, `actions`, `children`; независимые `onOpen` и `onSelectedChange` |
| `TaskCard` | Карточка задачи: `title`, `typeLabel`, `color`, `completed`, `onCompletedChange`, `menuItems`; остальные слоты наследует от `ContentCard` |
| `KanbanColumn` | `title`, `count`, `action`, `emptyState`, `children` для собственной композиции колонок |
| `KanbanBoard` | `columns`, `items`, `label`; действия `onMove`, `onCompletedChange`, `onOpen`, `onAdd`; необязательный `renderCard` |
| `DailyHeader` | `date`, `locale`, `showWeek`, `tags`, `actions`, `children`; `headingLevel` выбирает уровень заголовка |

## Состояние и данные

Потребитель хранит выбранные даты, текст, карточки, колонки, выделение и завершённость задач. Компоненты вызывают обработчики и не выполняют сетевые запросы, автосохранение или запись в `localStorage`. `onSave` редактора — запрос на сохранение; успешный результат подтверждает приложение после завершения своей операции.

`KanbanTask.id` и `KanbanLane.id` должны быть уникальными в своей коллекции. `columnId` каждой задачи должен указывать на существующую колонку: задачи с неизвестной колонкой не отображаются. Перемещение выполняется через меню карточки, доступное с клавиатуры. `onMove` сообщает намерение — он сам не меняет `items`. Перетаскивание не реализовано. При `renderCard` потребитель сам добавляет действия к своей карточке.

`ContentCard` — контейнер `article`. При `onOpen` только заголовок становится кнопкой; меню, чекбокс и кнопки в `footer` остаются отдельными элементами. При интерактивном содержимом `title` не передавайте `onOpen`, чтобы не вкладывать кнопки друг в друга. Для нетекстового заголовка передайте понятный `selectionLabel`. `density="compact"` уменьшает отступы; `orientation="horizontal"` размещает обложку сбоку на широком экране.

## Даты и клавиатура

Даты передаются строками `YYYY-MM-DD`, без времени и часового пояса. Не преобразовывайте выбор календаря через `toISOString()`: это может сдвинуть день. `defaultMonth` принимает `YYYY-MM` или полную дату и задаёт начальный месяц, когда `value` не выбран. При внешнем изменении `value` календарь показывает месяц выбранной даты.

`locale`, по умолчанию `ru-RU`, форматирует названия месяцев, дней и даты. Подписи служебных кнопок остаются русскими. Неделя начинается в понедельник, сетка всегда содержит 42 дня; `DailyHeader` показывает номер ISO-недели. `today` позволяет задать локальную дату «сегодня», например для детерминированных примеров. `yearRange` задаёт доступный диапазон списка годов; `min` и `max` ограничивают сам выбор даты.

- Стрелки перемещают фокус на день или неделю; недоступные даты пропускаются.
- `Home` / `End` переводят фокус к началу / концу недели.
- `PageUp` / `PageDown` меняют месяц, с `Shift` — год. День месяца ограничивается последним существующим днём, например 31 января → 28 февраля.
- `Enter` / `Space` выбирают сфокусированную дату. Переход стрелками сам по себе не меняет `value`.
- `min`, `max` и `isDateUnavailable(date)` исключают выбор и клавиатурную остановку на дате.

`CalendarEvent` содержит `id`, `date`, `title`, необязательные `time` и `color`. События отмечаются точками; `showAgenda` показывает события выбранного дня. `time` — готовая строка для отображения, а не объект времени. Планирование и проверка пересечений принадлежат приложению.

## Markdown

Поддержаны заголовки, абзацы, жирный и курсивный текст, встроенный код, блоки кода с тройными обратными кавычками, плоские списки, задачи `- [ ]` / `- [x]`, цитаты, разделители и ссылки. Ссылки допускают `http`, `https`, `mailto`, якоря и абсолютные пути внутри сайта. HTML выводится как текст; небезопасный URL не становится ссылкой.

Это небольшой текстовый редактор с предпросмотром, а не полный rich-text редактор или реализация всего CommonMark. Вложенные списки, таблицы, изображения, HTML и расширения не поддерживаются. Чекбоксы в предпросмотре показывают состояние; меняйте исходный текст, чтобы отметить задачу. Вложенное форматирование внутри выделения поддерживается только в пределах простого поднабора.

Кнопки форматирования обрамляют текущее выделение. `Ctrl/Cmd+B` — жирный, `Ctrl/Cmd+I` — курсив, `Ctrl/Cmd+Enter` вызывает `onSave`, если он задан. `readOnly` блокирует изменение, `disabled` дополнительно выключает поле. `headingOffset` у предпросмотра по умолчанию равен `1`: Markdown `#` становится `h2`, чтобы не создавать второй заголовок страницы `h1`.

## Композиция с панелями

Используйте `ActionBar` для группы инструментов с навигацией стрелками, `ButtonGroup` для визуального объединения и `SplitButton` для основного действия с дополнительным `Menu`. Они принимают `size="xs" | "sm" | "md" | "lg"`; выбранный размер согласует вложенные кнопки, Menu/Popover triggers и поля. Вложенная группа может переопределить size. `Popover.size` влияет на trigger, содержимое popup сохраняет собственную геометрию. Если внутри панели есть поля ввода или сложные управляемые элементы, установите `rovingFocus={false}` и оставьте обычный обход по `Tab`.

`ScrollArea` добавляет краевые маски только со сторон, где остаётся прокручиваемое содержимое: они открывают существующий фон без цветной подложки. `scrollbar="auto" | "hidden"` управляет полосой, сохраняя wheel/touch/keyboard; горизонтальный режим по умолчанию hidden, vertical/both — auto. `shadows={false}` отключает маски. Задайте контейнеру ограниченную высоту; `ref` указывает на внутренний прокручиваемый viewport. Канбан имеет собственную горизонтальную область: не оборачивайте его второй горизонтальной прокруткой без необходимости. На узком экране редактор в режиме `split` складывается вертикально.

`Dialog` / `Drawer` подходят для создания и редактирования карточек; `FloatingField` размещает подпись внутри поля. `StatusBar` показывает результат действия: `variant="plain"` по умолчанию оставляет фон прозрачным, `variant="surface"` добавляет подложку. `Alert` показывает подробное состояние или ошибку. Видимость диалога, результат сохранения и время показа уведомления контролирует приложение. Размеры, плавность, фокус и reduced motion уже заданы общими стилями.

ContentCard/TaskCard, MarkdownEditor и popup используют поверхность raised; SidebarPanel и панель форматирования редактора используют canvas. Popup сохраняет локальные тему, акцент и borders, но устанавливает собственный raised-контекст. В собственных слотах не подменяйте фон без соответствующего data-surface: второстепенный текст и нейтральные/акцентные заливки вычисляются относительно этого контекста.

Рабочий пример: [`examples/WorkspaceV2.tsx`](../examples/WorkspaceV2.tsx). Он создаёт задачи, перемещает их между колонками, выбирает дату и редактирует заметку в локальном состоянии.
