# OTPInput

cp-107 · Component instructions

## When to choose

Use for numeric verification codes, with six digits by default. Use Input for arbitrary text and NumberField for quantities.

## How to use

Keep `value` as a string and update it through `onValueChange`; never convert the code to a number. `length` accepts 1–32 digits and `size` follows the shared scale. Input defaults to `inputMode="numeric"` and `autoComplete="one-time-code"`. Supply one label through `label`, `aria-label` or `aria-labelledby`. The consumer owns submit, clear/reset and server validation; entering the final digit does not submit automatically.

## States and accessibility

One real native input owns focus, selection, copy/paste, autofill and form submission. Visual slots are decorative. `ref` targets the native input. `hint`, `error` and extra `aria-describedby` IDs stay associated with it. `disabled` removes editing and form participation; `readOnly` permits focus, selection and copying. Native form validation requires the full configured length. Non-ASCII/non-digit characters are removed and excess digits truncated. Physical-device OS autofill needs separate verification.

## Do

- Store `"012345"` as text; clear by setting `value=""`.
- Let the form handle submission and validation with a normal submit button.
- Show a useful error after an unsuccessful verification.
- Verify that every slot fits the actual field container at narrow widths, including `xl` and long labels/hints.

## Don't

- Convert the code with `Number` or `parseInt`.
- Auto-submit or move focus on the final digit.
- Create a separate focus target for each digit.
