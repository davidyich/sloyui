# RichTextEditor и исходный Markdown

Канонический редактор — `RichTextEditor`: контролируемые JSON-блоки со стабильными ID. `MarkdownEditor` остаётся устаревшим экспортом для совместимости; новые интерфейсы используют `RichTextEditor` и Markdown-мост.

`markdownToRichText(source)` и `richTextToMarkdown(document)` связывают редактор с Markdown. Блок хранит необязательные `markdown`-метаданные: точный исходник, разделители, язык и длину fence, отпечаток содержимого. Не удаляйте эти метаданные при сохранении JSON, если нужен дословный обратный перевод. Сохранение нетронутых блоков не меняет пробелы, CRLF/LF, нумерацию, обозначения marks или исходный язык fence.

Визуально редактируются H1–H3, простые абзацы, отдельные пункты списков, однострочные цитаты, простые bold/italic/strike/inline-code и fenced code. Таблицы, ссылки, HTML, вложенная разметка, frontmatter, экранирование и остальные неподдерживаемые конструкции остаются редактируемыми блоками `markdown-source`, без исполнения HTML. Для сложной композиции и любых исходных конструкций переключитесь на полный Markdown. Изменённый rich-блок сериализуется в канонической записи; остальные блоки сохраняют точный исходник. Преобразование opaque-блока в другой тип через меню — явное действие пользователя.

Это мост малого подмножества, а не полный CommonMark-парсер. Не используйте его для выполнения HTML или для автоматической нормализации произвольной разметки. Потребитель владеет исходной строкой, хранением и разрешением конфликтов.

## CodeBlock

`filename` необязателен; `label` остаётся совместимым alias, `filename` имеет приоритет. Расширение имени определяет начальный язык, если не заданы `language` / `defaultLanguage`. `variant="auto"` следует Borders-контексту: Off даёт заливку, On — контур без заливки тела; `surface` даёт заливку, `outline` — контур без заливки, `filled-outline` — заливку с явным контуром. Не вкладывайте второй оформленный `pre` в компонент: он рисует единственную внешнюю рамку. Заголовок отделён спокойной поверхностью и одним декоративным разделителем, который следует Borders. Радиус, цветовые роли и поверхность берутся из локального контекста.

`lineNumbers` добавляет отдельный декоративный gutter, скрытый от assistive technology и выделения. При `wrap` его высота следует фактической высоте строк через ResizeObserver. Номера не входят в `code.textContent` или копируемый источник; пробелы, CRLF/LF/CR, многострочные комментарии/строки и завершающий перенос сохраняются. Подсветка выводит escaped React-текст, без исполнения HTML. Это небольшая лексическая подсветка, а не полный парсер языка. Слот `editor` сохраняет свою область редактирования и не получает gutter.

Рядом с копированием находится Menu с переносом строк и необязательными `contextActions`. `showActionsMenu={false}` скрывает его; `actions` остаётся слотом отдельных действий. `wrap` + `onWrapChange` задают управляемый перенос. `editor` — слот редактора кода; `children` всегда содержит точный источник для копирования. Редактируемый элемент слота должен иметь доступное имя и видимый клавиатурный фокус. RichTextEditor использует этот слот для многострочного кода; Enter вставляет новую строку, Ctrl/Cmd+Enter создаёт следующий блок. Marks не применяются к source/code-блокам.

## Инструкции каталога

`demo/Documents.tsx` открывает Rich edit и предоставляет вкладку Markdown. В обоих режимах сохраняется одна исходная строка и один sessionStorage-черновик. Смена режима сама по себе не меняет файл или dirty-состояние. `preserveMarkdownSourceEdit` компенсирует нормализацию переносов нативным textarea: неизменённые префикс и суффикс сохраняют точные LF/CRLF/CR, новые строки используют существующий стиль. PUT продолжает отправлять исходный текст с ревизией настоящего файла; ошибка конфликта оставляет черновик. Новая ревизия принимается только после просмотра версии на диске и явного «Продолжить с моим текстом».

`MarkdownRichTextEditor`-композиция реализована внутренним адаптером `src/components/markdown-rich-text-editor.tsx`; отдельная каноническая страница для него не требуется.
