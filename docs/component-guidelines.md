# Component composition

Read the selected `agent-manifest.json` record for exact props, defaults, keyboard behavior and related components. Reuse an exported component and typed variant; application layout, data, persistence and network operations belong to the consumer. Read `surface-context.md` for paint and context, `recipes.md` for compositions.

## Choose by intent

- Use `Tag` for chromatic labels, `Chip` for neutral choices, `Counter` for counts and `TextAction` for text actions. Badge/TypeLabel are compatibility wrappers; MarkdownEditor redirects to RichTextEditor. Keep one canonical page.
- Use Input/Textarea for text; Input labelPlacement="inside" replaces the archived FloatingField compatibility wrapper and its catalogue route. Use DatePicker for dates, NumberField for numbers, ColorPicker for colors and Select/ComboBox for choices. NumberField retains partial edits and clamps out-of-range input on blur. No visible browser picker input types. MultiSelect uses neutral selected chips; TagInput handles free tags. Use one label source and preserve label/id/hint/error wiring.
- Use Tabs variant="workspace" for workspace sections with item icons and an optional trailing action. Use KanbanColumn variant="framed" with icon/action/footer slots for framed task groups; ButtonGroup appearance="framed" groups their actions.
- Use ButtonGroup for visual grouping, ActionBar for arrow-key navigation and FloatingActionBar for floating actions. A nested explicit size overrides group sizing. Popover size changes only its trigger.
- ButtonGroup hover/pressed are child paints over the painted group background. Replace the child's current state paint; do not composite hover and pressed together or measure either directly against the region background. Check text on the framed count section's actual backing too.
- Use TreeView for hierarchy, FileTree for files and separate previews, PreviewRail for compact destinations with transient previews. Metadata inside row buttons must remain noninteractive; put actions outside them.
- Use controlled Dialog/Drawer/BottomSheet for modal flows. Reuse their portal, trap, inert background, scroll lock and focus restore. Only BottomSheet's handle starts dragging; keyboard snaps and pointer cancellation remain available.
- Use ContentCard for configurable content, ReorderableList for controlled vertical order, KanbanBoard for columns, card-body drag and keyboard/menu moves, DataTable for sortable/paginated data. Consumers persist changes and supply stable unique IDs. DataTable columns accept pin="left|right" and footer summaries; maxHeight/minWidth bound the scroll viewport, stickyHeader pins the header, pinnedRows uses row IDs for top/bottom rows and pinSelection controls the selection column. On narrow containers, excess pins release automatically to reserve a readable scroll lane. Structural grid boundaries stay visible with decorative borders off.
- Use charts for their data shape: Line/Sparkline/Brush for trends, Bar/Slope/Gauge for comparisons, Donut/Waffle/Treemap for proportions, Streamgraph/Ridgeline for distributions, ActivityHeatmap for daily activity. Keep the accessible data table available.

## Language and formatting

LocaleProvider requires locale="ru"|"en" and applies to its descendants; the default context without a provider is Russian. useLocale() returns the current language; useTranslate() returns t(ru, en) for consumer-owned interface strings. Built-in text and default Intl formatting follow the nearest provider. Explicit locale props or formatting callbacks override Intl where supported. Consumer labels, content, data, filenames and custom presets remain unchanged. LocaleProvider and its hooks are utilities without separate catalogue pages.

## Geometry and controls

Use Medeo Sans, semantic size tokens and weights 400/500/600. Control size selects a role within the current Density mode; the v4 md control is 32 px in Default and 30 px in Compact. Dialog/Drawer size sets panel width. Component size never changes action meaning or color. Controls with the same appearance and visible height must use the same radius and horizontal padding; the presence of a label, value or icon does not create another geometry. On touch, choose accessible hit areas; compact tags and xs do not automatically grow.

`data-radius=none|compact|default|rounded` is independent of surface with base corners 0/4/8/16 px and defaults to 8 px. Authored and generated length radii are whole pixels; derived corners round to the nearest whole pixel after the complete inset calculation. None uses 0 px corners and no radius-only optical insets; Rounded adds corner clearance where needed through `--cap-radius-inset`; FloatingActionBar keeps its positive-radius padding fixed. Multiply fixed corner additions by `--cap-radius-enabled` so None stays square. Preserve centered icons and explicit circle/pill shapes. For nested controls, preserve the chosen inner radius and derive the shell from the actual padding plus structural border; use the same geometry for hover layers. Large rounded shells also increase optical content clearance: add the local `--cap-radius-inset` once at each actual outer content edge, including headings, the first/last content rows and actions. Keep header/body/footer side insets aligned; preserve section gaps and avoid doubled padding on nested wrappers. Verify Rounded at Compact density and narrow widths. Headings must never crowd the curved edge. Leave equal code insets left/right/bottom and room for focus outlines; avoid clipping at narrow widths.

`data-density=default|compact` selects v4 Density adaptive roles. Use round(k × u) spacing and line-height + 2 × vertical padding for controls, where u is 4 px in Default and 3 px in Compact; fixed roles remain unchanged. Compatibility bindings are in `source/density.json`; keep raw primitives immutable, type sizes unchanged and coarse-pointer targets at least 44 px. Portals inherit the nearest density live. Inside-label fields coordinate height, text and icon insets. Square floating/attached groups use zero shell padding and action gaps, larger content insets and full-cell hover; borders remain independently available. FloatingActionBar positive-radius insets depend on density and size only.

Neutral primary/secondary buttons preserve the local accent context. Accent variants use its paired solid/soft roles. Framed ButtonGroup has one toggleable outline and a surface-aware fill; its child frame must not add a second outline. Checkbox/Radio/Switch/RadioGroup default contrast=true uses the local solid accent pair; contrast=false uses the soft local accent pair, which is the default for Slider. A neutral Switch uses action roles in Primary mode and control roles in soft mode. Slider track/thumb radius follows context and never exceeds half its size. Marks/thumbs use matching text roles. Ghost fields react on hover/focus without losing semantics. Field focusRing overrides inherited width/offset. Hover uses semantic fill without a native/system black outline. Keyboard focus uses the kit’s semantic ring with the same radius as the control and stays visible when borders are off. An independent data-focus-ring="off" explicitly hides the focus outline, and on restores it in nested contexts; remove a native outline only after providing that replacement.

Figma mockup controls use independent Accent modes: Neutral by default, Blue, Green, Yellow, Orange, Red, Pink and Purple. Apply the mode on a containing frame and leave instances on Auto; explicit hue roles still support several colors in one composition. Native Primary/Secondary controls map to web primary/secondary in Neutral and accent/accent-secondary with the selected data-accent in chromatic modes. See [controls coverage and migration status](../figma/controls/README.md); instance variants do not establish working prototype behavior.

Native Figma dimensions resolve to whole pixels and export only needed integer FLOAT primitives. Color alpha belongs to the composed fill/stroke; do not fade a complete control layer because that also fades text, icons and focus. Custom background changes require regenerated role bindings for that declared backing; controls do not inspect arbitrary DOM or Figma backgrounds. See [surface contract](surface-context.md).

Card, ObjectCard, ContentCard and FileCard preserve the parent Surface and paint its block role; Card subtle paints bg and elevated adds a shadow. Set data-surface explicitly only when the region has a different purpose. Card keeps its structural `.cap-surface-boundary` when decorative borders are off. Add that class to a custom nested surface intentionally sharing its parent’s surface role; paint it with the matching semantic role and declare context explicitly. Do not infer surface from background or add structural outlines to every control.

Tag variant="plain" is a text label without a resting background or outline; it inherits text color and keeps interactive focus indicators. Use it for instruction-language markers. Tag.interactive=false disables every action slot. Share one action hover surface. Counter starts square and grows with content. Icon-only actions need an accessible action label and a compact tooltip on hover and keyboard focus; reuse the label, let an explicit tooltip replace the automatic hint, and avoid native title duplicates; use IconPicker's visual search for icon settings.

## Behavior and accessibility

Consumers handle empty/loading/disabled/error states and prevent repeated actions while busy. Error includes a text reason and aria-invalid; color alone is insufficient. EmptyState icons are optional, neutral and quieter than text. Do not nest buttons/links inside ObjectCard, CollectionRow or interactive titles.

Keep native keyboard and reduced-motion behavior. Tabs need unique values, a valid active value and group label. Radios in one group share a name. Tooltip accepts one focusable element forwarding aria-describedby; its content is noninteractive. Its text shell keeps an 8px radius (0 in None) and fixed 12px inner clearance across radius/density contexts. Tooltip maxWidth defaults to 288px and clamps to the viewport; prose and long identifiers wrap. Use Popover for actions. Select's hidden native input preserves form submission.

PopupSelect opens an independent-width list without search by default. Set searchable=true only when filtering is useful; searchPlacement=inline shares the list surface and separate gives search its own field. Both use row-height geometry. Group captions use content/caption, regular weight and sentence case. Use a labelled trigger with triggerContent for a compact swatch/icon; keep its contents noninteractive. popupWidth is constrained to the viewport. Options support leading/icon, description, aliases, group, meta and triggerLabel. Value and open may be controlled independently; name enables native form submission/reset/required validation. Arrows/Home/End skip disabled options, Enter selects, Escape restores trigger focus and Tab leaves the control. Without search the listbox receives focus and supports typeahead. Portals inherit every context axis and establish Floating. Pointer movement changes the active highlight without scrolling; keyboard/filter changes reveal it.

Menu.triggerContent replaces its icon with noninteractive content inside the same labelled button. Use a static Tag for status selection; never nest an interactive Tag or another button. The custom trigger keeps the menu's arrows, typeahead, Escape and focus restoration.

Transforming panels reuse the shared kit duration/easing and presence behavior, including reduced motion; do not add a private animation system. Use opacity/transform for finite motion, never transition:all or permanent will-change. Shared highlights may morph the box of their small absolute layer with one finite animation; avoid scale distortion of corners, batch geometry reads, preserve the current visual box on interruption, and preserve opaque controls’ resting paint. FloatingActionBar puts static control fills below one moving hover plane and foreground above it; never hide neighboring fills. Ordinary opaque groups without separated paint planes retain local hover. Exit fades preserve the current box. Pointer hover must not return to a stale mouse-focused control on exit; only keyboard-visible focus may own the layer after the pointer leaves. Opening and closing a popup reconciles its trigger with the shared layer. Small disclosures animate both directions (180 ms), retain exiting content briefly, immediately remove it from input/focus, and restore focus to a visible ancestor. Each exit owns its deadline; reopening cancels removal. Reduced motion completes immediately.

ScrollArea owns bounded local scrolling; its ref targets the viewport. Horizontal scrollbar defaults hidden, vertical/both auto. fade accepts true/false, none, an axis, a physical edge or logical start/end (RTL-aware). Explicit fade overrides legacy shadows; fade=false disables it. fadeSize accepts px as a number or a CSS length, default min(12%, space-10). fadeReveal is the scroll distance in px for gradual reveal, default 2 × space-12; 0 reveals immediately. No overflow leaves content unfaded. Small edge gradients use the current semantic surface to shade only the viewport edges. They do not mask its contents or read computed styles on each scroll. Place floating controls through ScrollArea.floating outside the viewport, reserve clearance and preserve shadows. Never disable scrolling or add outer overflow:hidden to hide a defect.

## Content and editing

MarkdownEditorV2 controls a Markdown string through value/onValueChange and defaults to contextual editing; onCommentRequest delegates selected text to the consumer. RichTextEditor keeps its classic UI by default and offers uiVariant="context" for the same selection toolbar/block menus. Colors/highlights serialize as data-cap-color/data-cap-highlight spans, underline as HTML, tables as pipe Markdown, and toggles/callouts as supported extensions. Plain Markdown readers may not render those extensions. The archived MarkdownEditor compatibility route remains redirected to RichTextEditor.

RichTextEditor stores blocks with stable IDs. For Markdown strings use markdownToRichText/richTextToMarkdown and retain block.markdown metadata; unsupported syntax stays editable source. Drag uses the block handle only; preserve move-menu and keyboard alternatives, Escape/cancel and source text. Read-only/disabled hides editing handles. showToolbar=true opts into the top toolbar; it defaults false without disabling editing or selection tools. Native mouse/Shift selection can span text blocks; copy/cut and typed/pasted/deleted replacements preserve unselected blocks and their IDs. Keep Markdown source metadata when editing; do not silently rewrite unsupported syntax.

ContentCard accepts stable blocks/blockOrder/hiddenBlocks. Use slots and its dragHandle instead of forking. selectable=false suppresses checkbox and selected paint; omitted enables selection only with onSelectedChange. Mixed orientations must not stretch to the tallest neighbor. Leave 12 px around a protruding selection control. ReorderableList is controlled with grip-only drag plus keyboard/click alternatives. KanbanBoard uses stable task/column IDs and controlled onMove(id,columnId,index); index is zero-based in the destination after removing the source task. Persist both column and order. Drag commits only on drop; Escape/pointercancel cancel. Card-body drag is default and excludes buttons, fields, links and editable content; dragActivation="handle" opts into a grip. Focused card/grip arrows change order/column; menus offer the same moves. Custom cards place context.menuItems in action slots; optional grips use dragActivation="handle", handlePlacement="custom" and context.handle. KanbanLane accepts variant/icon/action/footer for column composition.

Calendar uses local YYYY-MM-DD dates. Kanban tasks point to existing column IDs; onMove reports intent and does not mutate items. Rich text, table sorting/filtering and pagination remain consumer state. MarkdownPreview never renders arbitrary HTML.

CodeBlock copies unchanged source. Use filename (label is an alias), language/onLanguageChange or defaultLanguage, lineNumbers, contextActions and onWrapChange. With showActionsMenu, the sole wrap action is an icon button whose tooltip describes its next action; adding contextActions switches to a menu. Direct actions and custom action slots precede Copy; the multi-action menu follows Copy. Do not add a second wrap control. variant=auto respects borders; surface/outline/filled-outline select explicit paint. density=compact (default) or comfortable sets shared spacing for all CodeBlock variants; header controls have equal outer insets, and labels align with code text. Accent controls use the local secondary hover/pressed pair. headerVariant=unified shares the body fill without a header divider; separated is the default. tabs accepts unique value/label/code entries with optional language/disabled; tab/onTabChange controls selection, defaultTab initializes it. Invalid or removed selections fall back to the first enabled entry; empty/all-disabled tabs use children. Copy always uses the active entry, without tab labels. Tabs can represent commands, stacks, platforms or any consumer-defined options; use stable values and a meaningful tabsLabel. Command tabs use compact controls, a moving secondary hover fill without outlines and an inset keyboard focus ring; the code viewport owns the body focus indicator. tabsLabel names the accessible group; stack tabs replace the syntax-language chooser. color=inherit uses the local secondary accent on every surface. editor replaces only the code body. In narrow API panels keep equal visible insets, no clipping and no document overflow.

ContentLayout controls width/height per orientation, with independent left/right panes and axis bounds. contentWidth is separate from pane size. divider controls decoration, not resize semantics. collapseAt uses container width; parent available space overrides minimums. Bound vertical height explicitly. Resizing supports arrows, Shift, Home/End, Escape and pointercancel; closed panes release capture. ResizableCard keeps desired size while fitting its parent, commits only completed changes and allows inner scrolling.

ResizablePanelGroup uses direct ResizablePanel → ResizableHandle → ResizablePanel children, horizontal by default. Nest a group inside a panel for another axis; bound vertical height. layout/defaultLayout and Panel defaultSize/minSize/maxSize are numeric percentages of usable panel space; unspecified initial sizes share the remainder. Infeasible bounds adapt only enough to fill the parent. Controlled layout needs onLayoutChange; onLayoutCommit persists a completed change. Handles overlap the actual shared boundary with zero net layout width; never add a gutter for their hit area. The shared affordance is also used by ContentLayout, Palette Lab and catalogue inspectors. Handle appearance="line" reveals a quiet grip on hover/focus/drag; appearance="grip" keeps it visible (withHandle is compatible); label names the separator, and disabled removes it from Tab while keeping pane content active. Arrows change step (default 1%), Shift multiplies by 10, Home/End respect adjacent-pair bounds and Escape cancels drag. Zero-size panes are inert. No handle appearance draws a full-length divider, including with Borders On. Panel surface defaults inherit; composition owns paint and structural boundaries. Use ContentLayout for pixel side panes and responsive stacking; use ResizableCard for one bounded card.

Toast/Alert/StatusBar share tone/color/appearance/contrast/surface. Neutral Alert/StatusBar shells color only the status icon; neutral Toast with contrast=true uses the black/white action fill/text pair. Inline feedback inherits surface, Toast defaults floating. Consumer controls lifetime/dismissal; keep actionable content until explicit dismissal. ToastStack uses position=top-center|bottom-center for centered placement; scope=viewport portals to the overlay layer, scope=container requires a positioned parent with a bounded height. shape=pill opts into capsule geometry; rounded follows radius context. Unread rear notices and loading states pause expiry; actions require explicit dismissal. Stacks use measured item geometry and expandDirection=up|down|left|right; reserve shadow clearance and permit internal scrolling. ToastStack.showExpandHint displays an integrated visible-item count; false keeps the keyboard toggle visually hidden. Hover/focus and a touch on the front notice expand the stack. No detached chevron is painted. Reflow starts from the current visual geometry even when interrupted. ToastStack scrollbar indicators are always hidden, including expanded/overflow states. AnnouncementBar rotation pauses with focus/hover/pause; TextShimmer pauses offscreen/hidden and remains readable with reduced motion/forced colors.

## Catalogue and instruction maintenance

source/component-registry.json owns permanent IDs, status, primaryGroup and every membership. Renaming/reordering never changes IDs. New components remain needs-review until reviewed; archives stay exported but leave canonical counts and route to replacements. Regenerate the manifest and keep one typed Playground per canonical component. Expose meaningful public props/slots; do not repeat global context controls.

Catalogue Surface/Accent/Density/Radius choices use PopupSelect. Focus color triggers show only a swatch and chevron, while the popup searches semantic names and CSS aliases. Playground preview/settings share ResizablePanelGroup; settings wrap within their pane and stack below preview at narrow container widths. Preserve edited values during resizing.

API rows derive from exported TypeScript signatures and JSDoc through scripts/build-reference.mjs; do not infer defaults from Playground state or maintain a duplicate props table. Usage/agentNotes/related belong to the manifest generator. Preserve canonical case-sensitive #ComponentName routes, Workspace navigation and Content main-region paint. Preview surface changes affect the examples; keep the root at Shell, headers and instructions at Content, and catalogue settings at Overlay. Use `.cap-surface` on painted regions so both background and inherited text resolve in the local surface context. Catalogue scrolling belongs to .catalog-main.

The core instruction files, catalogue-maintenance guide and GitHub task workflow are listed in demo/document-files.ts and protected from deletion. The local editor writes actual repository files; the production owner editor uses persistent SQLite documents and file mirrors. Custom Markdown files live under docs/instructions/; component instructions live under docs/components/<stable-id>.md. Each canonical component has individual guidance and Do/Don’t examples read through its existing history API; the build includes these files in documents.json while the general instructions list hides them. List files dynamically and check revisions for save/delete. Drafts survive conflicts; never silently overwrite them. Custom filenames use letters/numbers/hyphens/underscores and .md. Guests have read-only access; see catalogue-maintenance.md for version/history maintenance. Reusable rules belong here, in surface-context.md, recipes.md or AGENTS.md; replace obsolete text rather than duplicating rules across revision notes.

FileCard represents a file attachment with an optional thumbnail and inferred MIME/extension kind. Pass a display-ready sizeLabel; the consumer owns URLs and open/download/remove operations. Actions are siblings, filenames retain their full accessible text, failed previews use the format tile. Use FileTree for hierarchy.

Accordion hover belongs only to its summary; the expanded body keeps its background and equal content insets. Use `Accordion.chevronPosition="end"` for a trailing down/up chevron in settings rows. Disclosure chevrons morph their points between states instead of rotating. Preserve the current shape when reversing a transition and honor reduced motion.

Catalogue uses five navigation/overview sections from registry.navigationGroups; detailed groups remain filter facets. Assign each entry once by primaryGroup. Collapse/expand all changes only visible group expansion, preserving route, query and filters. Catalogue status labels are Ready (quiet neutral), Review (pink), Rework (orange), Archived (gray). Hide archived components from default navigation/search/overview; show them only through the Archived filter. Archives without replacements keep their direct pages and exports; compatibility aliases keep their replacement routes.

- Foundation examples inherit the catalogue accent: omit fixed `color` props unless comparing named palettes or semantic statuses. Geometry samples use accent roles; documentation emphasis and text selection use paired accent ink/background roles, while code-block syntax keeps its own palette.

- Interface text uses `--cap-line-height-*`. Long prose uses `--cap-prose-line-height-*`, a measure of at most 70ch and paragraph spacing; headings and code keep their own rhythm.
- Catalogue previews start without optional visible labels or hints; keep an accessible name and expose label/hint controls. Component IDs sit quietly at the top-right of the page heading.
- Select appearance="parameter" places its single label at the start and selected value at the end inside one full-row hover target. Do not wrap it in a second row label or override its trigger background.
- ParameterSlider keeps label/value in one standard-height filled row. showHandle adds a 2px semantic-gray grip at the fill boundary without increasing height; paint the short grip beneath text without masking its bounding boxes, so it stays present while crossing labels. Borders follow the same semantic control boundary as fields without changing geometry. Use a quieter fill in Light while preserving a distinct filled portion and gentle hover. Keep backdrop stable and react through fill and grip opacity; the short grip stays quieter than the label. Optional showTicks marks actual step positions when there are at most 21; dense ranges omit marks. Native range keyboard/forms, relative grip dragging and cancellation remain intact.
- Slider2D exposes independent x/y ranges, step/fineStep, end labels and reversed direction. Y increases upward unless reversed. Pointer changes coalesce per frame; release commits and Escape cancels. showFields=false is the default: exact lower NumberFields are optional; hidden accessible axis ranges keep keyboard access when the visible fields are omitted. Keep onValueChange fast and save with onValueCommit.
- SelectOption.meta is a noninteractive right-hand slot; triggerLabel optionally shortens the closed value while label remains the option name and typeahead source. Expose both in the Playground.
- Tabs defaults to `variant="segment"`; choose `variant="line"` explicitly for underline tabs. Tabs, SegmentedControl and OverflowTabs inherit `data-radius`; inner selected/hover surfaces keep the selected control radius, with the shell growing by the actual inset. Segmented size sets the full inner control height; shell padding and border are added outside it. Segmented gaps equal the visible outer inset (padding plus border); moving layers preserve fractional border widths. Moving highlights use `data-visible` as their single visibility source and remeasure when ancestor `inert` or `aria-disabled` changes; leaving a hover target must not hide selection. Line tabs use immediate local hover, without a moving highlight. TreeView keeps selection below its moving hover layer and row content/focus above both, with or without guides.

- FocusRing supports width/offset in pixels and colorToken from the exported focusRingColorTokens list of public STROKE_COLOR roles. Prefer semantic references over literal colors; offset defaults to 0 and fractional widths such as 0.5 are supported. Focus outlines are enabled by default and independent of decorative borders; data-focus-ring="off" explicitly disables them, including in inherited overlays.
- CommandPalette defaults to showTitle=false; it keeps an accessible heading and places search beside close; result scrolling stays between the fixed header/footer with surface edge gradients. Use one moving active-result indicator for pointer and arrow navigation; reveal offscreen results only for keyboard/filter changes, never hover. Register global shortcuts in the consumer.

- Breadcrumbs items accept collapsed=true to display an ellipsis while retaining the full accessible label. Keep the final/current item explicit; supply href on an actionable collapsed ancestor.
- Rounded controls scale their radius with visible size: 25% of control height at the default base, multiplied by the radius mode and capped at 37.5%. Derived corners round to whole pixels. Explicit pills/circles remain circular; None gives zero. Menu and attached-action shells add their actual padding and structural border to the inner control radius. Never scale the outer and inner corners independently. Full-bleed render slots inherit their shell radius; only a real inset creates a different inner corner. Legacy raw actions use the same visible-height formula based on their line box and vertical padding. Segmented controls and tabs use the same outward formula. `data-corner-shape="round|squircle"` inherits independently through portals; native `corner-shape` progressively enhances supported browsers and leaves circular/pill geometry unchanged. Squircle concentric spacing uses the library-derived 1.84 approximation; ordinary corners use 1.

Checkbox, Radio and RadioGroup use the local focus color for unselected control outlines; it remains visible regardless of Borders and adapts to the surface. Selected states retain their accent.
