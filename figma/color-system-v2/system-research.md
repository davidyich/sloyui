# Подходы к цвету для Sloy UI V2

Проверено 2026-10-16 по публичной документации Interfere, Radix, Carbon и Spectrum. Ниже отдельно указаны наблюдения и решения для Sloy. Это исследование цветовой архитектуры; реализация компонентов этих библиотек целиком не аудировалась.

## Interfere

[Colors](https://design.interfere.com/colors/) разделяет фон области (`page`, `shell`, `container`, `card`, `sunken`, `modal`, `standout`) и заливки контролов (`component`, состояния и варианты `on-sunken`, `on-inverted`, `on-container-subtle/strong`). Есть отдельные transparent-роли, foreground, border и парные `on-solid` / `on-subtle` цвета для brand/status.

Для Sloy полезно это разделение по назначению. Shell/Workspace/Content/Overlay описывают область; Primary/Secondary/Tertiary — выразительность элемента внутри неё. Локальная серая карточка не обязана создавать новую Surface. Наше исправление прозрачных мягких акцентов решает частный случай «контрол внутри нейтрального блока» без дополнительных ручных `on-secondary` и `on-tertiary` режимов.

Копировать семь поверхностей буквально не стоит: это расширит выбор, но само по себе не устранит столкновения заливок. Названия Card и Component привязывают цвет к форме компонента, тогда как одна карточка Sloy может жить в нескольких контекстах. Полезнее сохранить существующие пять контекстов и явные правила вложенности.

В [Button](https://design.interfere.com/button/) отдельно показаны варианты, размеры, форма, pending и disabled; pending сохраняет подпись. В [Card](https://design.interfere.com/card/) поверхность, радиус и elevation представлены отдельно. Для будущих примеров Sloy полезна такая независимая демонстрация осей: изменение цвета не должно одновременно менять размер, радиус и тень.

## Radix

[Color](https://www.radix-ui.com/themes/docs/theme/color) содержит light/dark и прозрачные версии шкал, семантический выбранный accent, локальное переопределение цвета и high contrast. [Understanding the scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) закрепляет назначения ступеней: фон, состояния компонента, границы, сплошной акцент и текст.

Для Sloy берём принцип прозрачной мягкой заливки и проверяем её после композиции с реальным фоном. Это наше применение подхода Radix, а не импорт их палитры. На нейтральном Secondary полупрозрачный тег учитывает цвет контейнера; фиксированный opaque-образец этого не делает. Сильные Primary-заливки остаются непрозрачными.

Не требуется показывать пользователю Figma двенадцать номеров каждой шкалы. В Sloy остаются normal/active и три уровня выразительности. Ступени и подбор пигмента — внутренняя работа генератора. Полезный следующий шаг — различать hover и постоянный selection дополнительным индикатором или обводкой, сохранив две запрошенные заливки.

## Carbon

[Color overview](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview) определяет нейтральную модель слоёв: в светлых темах чередуются White/Gray 10, в тёмных вложенные слои светлеют. Роль токена остаётся стабильной между темами, меняется значение.

Для Sloy это аргумент в пользу проверки вложенных композиций и независимого переключения контекста. Но алгоритм Carbon нельзя переносить буквально: наш Dark Dimmed намеренно углубляет Workspace/Content, а Glass имеет собственный материал. Назначение Surface должно задаваться композицией; автоматический счётчик вложенности не заменяет его.

Практическое применение уже добавлено: четыре доски показывают одинаковые акценты на bg, нейтральных Tertiary normal/active и Secondary normal/active, во всех пяти Surface. Это проверяет отношения между слоями, которые не видны в обычной сетке отдельных свотчей.

## Spectrum

[Color system](https://spectrum.adobe.com/page/color-system/) описывает генерацию шкал через Leonardo с ключевыми цветами и целевым контрастом. UI-цвета могут отличаться от brand. Для заливки и контента используются парные цвета; тематические фоны проверяются вместе с текстом. Для категорий данных предусмотрена отдельная палитра.

Для Sloy берём целевые отношения и проверку пар после композиции. Равный номер ступени разных оттенков не означает равный контраст. Поэтому генератор подбирает существующую ступень цветного текста с учётом всех разрешённых нейтральных подложек, включая active и Glass.

Для универсальных дашбордов следующий самостоятельный блок — data visualization: категории, последовательные и расходящиеся шкалы. Пять UI-акцентов с мягкими тегами не следует автоматически объявлять палитрой графиков. В графиках нужны отдельные проверки различимости серий и связи цвета со значением.

## Принятые решения и дальнейшие кандидаты

| Подход | Решение для Sloy |
| --- | --- |
| Прозрачные мягкие акценты | Реализовано в 0.3 для Secondary/Tertiary; прозрачность заливки, а не всего элемента |
| Проверять вложенные слои | Реализовано: пять нейтральных подложек × двадцать контекстов, включая обе крайние подложки Glass |
| Группировка по роли | Реализовано: `surface/secondary/blue-normal`, `blue-active`, `orange-normal` рядом; `content/primary/blue` рядом с `neutral` |
| Стабильные смысловые роли | Сохранены IDs и логические ключи; имена в Figma меняются без повторного связывания макетов |
| Functional status aliases | Кандидат: success/warning/danger/info → существующие hue-роли; значение статуса независимо от выбранного brand accent |
| Selected + hover | Кандидат: отдельный индикатор selection; hover продолжает использовать active, без обязательной третьей заливки |
| Палитры графиков | Отдельный будущий контракт для категорий и числовых шкал; сейчас не внедрён |
| Независимые оси образцов | Сохранять Theme/Scheme/Surface отдельно от Density/Radius/Shadow; акценты доступны именованными цветами, без modes в будущей интеграции веб-кита |

Текущие гарантии цвета ограничены оговорёнными нейтральными подложками. Наложение красного тега на синюю заливку или произвольную фотографию без защитного Glass — другое сочетание, его нужно проверять отдельно. Акцентный Secondary не обязан иметь контраст границы 3:1: необходимая смысловая граница задаётся отдельной border-ролью.
